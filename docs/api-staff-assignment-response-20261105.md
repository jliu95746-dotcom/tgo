## 已修复的业务问题

1. **异常理由阻断分配。** 原代码允许模型的 `reasoning` 为对象、数组或布尔值，随后把它写入文本字段。真实持久化会失败并回滚转人工。现在只接受字符串或空值，否则在当前候选中按负载分配，保留受控兜底理由。
2. **不合法文本导致数据库失败。** 检查原始模型文本和解析后的理由，拒绝 NUL、无法编码为 UTF-8 的代理字符。原始文本无法存储时不保存该字段；安全可存储的原始模型响应仍可保留供授权审计。
3. **越界或无效模型选择。** 只允许当前候选集合中的 UUID。空响应、无效 JSON、非法类型、无效 Markdown 围栏和越界编号均不直接影响人员选择，转为负载分配。
4. **日志和错误提示泄露正文。** 不记录模型理由、无效编号原文、上游错误正文、请求查询参数和异常字符串。通用非流式客户端保留请求编号、方法、状态和安全错误类型；非限定的转人工异常返回固定提示，不把数据库错误放进 `TransferResult.message`。

正常 JSON、原先支持的 `json`/普通 Markdown 围栏、可选文本理由继续可用。系统提示词和用户提示词表达式经 AST 对照保持，模型参数、温度和 token 上限保持；没有调整生产开关或扩大自动回复范围。取消信号继续传播，不把取消变成一次新分配。

结果返回键保持原样，内部新增明确类型。既有权限和项目过滤保留；模型输出的候选校验只是其中一道检查，不替代真实渠道、当前成员状态和并发接待验收。
