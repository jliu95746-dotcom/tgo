## 修改与兼容性

本批 4 份文件：新增 Runtime 网络传输模块、修改现有 URL 解析器、新增网络边界测试及调整现有来源隐私测试的网络夹具；其他服务运行代码、模型、Schema、依赖和锁文件保持。

- 复用本服务现有的公网地址识别和 DNS 解析函数。每次连接及每次重定向重新检查解析结果：不能为空、最多 32 个地址、每个地址均须为公网地址。拒绝回环、内网、链路本地、元数据地址、共享地址空间、组播和包含私有 IPv4 的 IPv6 等结果；出现公私混合也拒绝。
- 实际 HTTP 连接使用已经验证的 IP，不再让连接阶段重新解析原域名；保留原 `Host`、端口和 TLS SNI，证书校验保持启用。客户端不使用环境代理或环境凭据，不进行网络重试。
- 每个候选配置文件的 DNS、连接、重定向和正文读取共用 **10 秒**期限；最多 **5 次重定向、6 次请求**，检测循环和缺少 Location，禁止 HTTPS 降级。GitHub/Gitee 的既有 main/master 和文件名回退仍可能尝试多个候选，10 秒不是整个 resolve 或 YAML 解析的总期限。
- 配置正文最多 **1 MiB**，先检查 Content-Length 的格式、长度和数值，再按实际读取字节计数；虚假的短长度不能绕过。请求声明只接收 identity，拒绝压缩响应，避免解压体积失控。重定向和非 200 响应的正文不读取，所有拒绝、超时和取消路径关闭对应上游响应。
- 只接受 GET 的公网 HTTP/HTTPS URL；**内网来源、URL 内嵌账号密码、压缩正文、超过上限或降级跳转现在会被拒绝**。没有增加自动允许内网或关闭证书验证的开关。公网自定义端口和正常签名查询参数仍保留。
- 以实际取得配置的最终文档目录解析相对 binary URL，随后既有解析步骤保持绝对地址。跨域 CDN 或变更目录的重定向不再把相对下载路径错误拼回初始来源。
- 来源抓取继续沿用安全日志范围和固定错误提示；安装、检查更新调用已有解析器，因此同样使用新网络边界。没有修改插件归属、生命周期状态或安装权限。

现有来源隐私测试改为只替代 DNS 与底层网络，保留真实传输保护。解析失败样本使用带合成查询凭据的合法公网 URL，并增加真实发起一次受控请求的断言；内嵌账号密码由新增用例独立验证拒绝。原有结果、相对地址、环境变量保留及日志保护断言没有删除或弱化。
