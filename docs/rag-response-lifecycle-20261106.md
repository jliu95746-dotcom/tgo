## 实现范围

1. **可用性返回与请求一致。** 核对项目、渠道、知识库编号唯一性及可用片段数不超过总数。合法空列表仍表示当前没有可用资料；错误状态、无效 JSON、错误形状、连接和超时转为现有受控错误，避免把错误内容当作业务结果。
2. **检索必须提供完整且属于目标知识库的资料。** 新增内部解析模型，要求存在 `results` 及完整正文，限制相关度为有限的 0～1 数值，检查返回知识库归属。保留正常响应的附加元数据、现有请求和合法 UUID 写法，不退回手动搜索接口。直接检索工具使用完整 `content`，对正文和文档编号进行 XML 转义；异常不再回显上游原文，正常空结果仍可区分。
3. **同步回执对应完整请求批次。** 成功、失败数量必须是非负整数且合计等于请求数；失败明细的数量与项目编号必须对应请求。错误明细仅保留项目编号和安全说明，固定维度约束说明仍可展示，不透传任意上游文字。
4. **部分失败分别记账。** 后台同步逐项目更新状态：成功项目清除错误并推进成功时间；失败项目保存安全错误摘要，保留上次成功时间。异常或无效回执继续遵循原有最多三次尝试和 1/2 秒退避；有效的部分失败回执不会立即重发整批成功项目。独立的既有周期重试机制保持。
5. **生产者保护错误信息。** RAG 写入单个配置失败时，返回通用失败说明，日志保留异常类型。既有逐项保存点、更新/创建、继续下一项及批次数量规则保持。本批测试中的写入异常由替身注入，不代替真实 PostgreSQL 事务恢复证明。

源码语法树核对：RAG 客户端 4 个实际 HTTP 调用的地址、方法、参数及载荷保持；生产者 5 处数据库调用保持；工具执行器其他方法保持。公开路由及生产者响应字段没有变化，新搜索模型为 AI 内部解析模型，嵌入回执计数约束收紧。未改 ORM、迁移、依赖、CI、权限或长期规则。
