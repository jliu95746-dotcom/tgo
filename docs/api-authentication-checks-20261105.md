## 修正内容

- 签名有效但 `exp`、`iat`、`nbf` 为 null、对象或数组的员工 JWT，统一拒绝；不让第三方库的 `TypeError` 成为内部错误。签名、用途、到期和当前数据库成员关系检查保留，既有合法及 legacy 凭证继续通过。
- 凭证解析返回经过严格校验的 JSON 值字典，替代业务接口中的 `Any`；编码和密码摘要输出检查真实类型，权限依赖工厂补齐类型声明。没有增加或改名对外 token 字段。
- 存储密码摘要损坏时验证返回 False，登录接口正常返回 HTTP 401；没有替换密码算法、修改密码或改变账号状态。
- 访客注册等待渠道、通知或 IM 返回后，若原渠道密钥被清空或替换为非 ASCII 内容，原访问正常被拒绝。密钥按 UTF-8 字节进行常量时间比较，保留当前渠道、企业和原始密钥一致性核验。
- 凭证失败、权限拒绝及员工登录/IM 同步日志不再写用户名或异常正文；保留必要事件及 `error_type`。登录成功、失败及 IM 同步失败三个分支均有日志回归。

这些缺陷使用合成输入复现，本批没有把它们记作已经发生的生产事故。其他端点、第三方库和日志路径没有因此被认定已经完成全局隐私审计。
