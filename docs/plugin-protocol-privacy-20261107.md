## 修改范围与行为

本批 7 份文件：Runtime 5 份源码、2 份新增测试；没有改动 API/AI 运行代码、模型、Schema、数据库迁移、依赖、锁文件、CI、权限、Skill 或生产配置。

- Socket 接收、注册拒绝、连接处理、绑定、文件移除和权限设置失败，使用现有操作名及异常类型日志，不记录原文或 traceback；普通连接日志也不回显未经校验的 peer、插件名称、版本或方法。
- 注册失败沿用 JSON-RPC `-32000` 及原请求编号。只有三个精确声明的原因可以返回：`Invalid dev_token`、`Invalid dev_token type`、`Debug connection requires dev_token`；未知值及 Pydantic 校验细节统一返回 `Plugin registration failed`，不按前缀放行。
- JWT 校验失败抛出固定 `ValueError`，在原异常处理块结束后再抛出，不携带其异常链。开发令牌的验证算法、识别字段、项目归属、数据库查找和未知 TCP 连接拒绝条件保持。
- 调度请求超时、发送失败、插件错误响应和面板解析失败，不再记录参数、远端错误对象或异常原文。成功结果原样传递；失败仍返回原来的 `None` 或跳过无效面板，pending future 清理和取消传播保持。
- 工具注册/删除保留原 URL、超时、JSON、请求头、prefix 和成功状态范围；日志保留固定动作及状态码，不读取响应正文作为诊断。沿用既有 HTTP 日志保护范围，插件名称和工具名称仍用于真实业务请求，不进入本批日志。
- 启动仍按 transport → process monitor → 已安装插件启动的顺序执行。初始化失败尝试停止 monitor 和 transport，清理错误同样保护，最后抛出固定 `RuntimeError`；没有打印 ready。正常关闭仍按插件连接 → monitor → transport 的原顺序。
- 已安装插件的自动启动查询和配置保持；该查询失败后仍沿用原行为继续启动 HTTP 服务，只显示固定提示和安全错误记录。这不表示数据库或自动启动已经恢复。底层 Socket 绑定函数仍保留原异常类型供内部调用判断，应用 lifespan 边界负责避免框架输出原始内容。
