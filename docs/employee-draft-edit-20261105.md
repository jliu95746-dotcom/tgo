# 员工草稿续办与业务配置修改（2026-11-05）

本批对应原计划的 AI 员工配置向导。独立保存岗位后，恢复草稿能取得原员工，但进一步修改企业信息或职责会因岗位归属冲突被拒绝；完成配置还会错误提示“创建成功”。本批将业务配置保存与独立岗位管理分开，沿用同一员工。

## 实现边界

- AI 在原账号事务锁内核对上次保存的员工实际配置与原草稿岗位。独立岗位存在、换岗或已移除时，允许保存新的业务配置修订，岗位内容、修订、编辑人和归属全部保留。
- 在独立岗位续办路径中，实际员工业务配置也被外部修改，或草稿原岗位/渠道发生变化时，拒绝覆盖；同修订内容冲突、旧修订、非本人、其他企业、已删除和已启用员工继续受原约束保护。原草稿仍拥有岗位时，沿用既有新修订保存行为。
- 返回保存快照的原岗位选择供 API 核验，不将其当作当前生效岗位；实时启用检查仍读取独立岗位。不会创建第二个员工、自动启用或生成新模型回答。
- Web 区分 HTTP 409 配置冲突与网络结果未知。草稿保留，提示先核对当前员工；完成向导统一提示“配置已保存，保持待启用”。列表刷新失败不会再次保存或创建。
- 无 API 字段、模型、数据库迁移、消息流协议和依赖变化，沿用当前页面风格及中文文案体系。
