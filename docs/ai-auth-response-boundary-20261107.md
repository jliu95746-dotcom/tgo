## 已实现

- JWT 声明经过 JSON 对象校验；`project_id` 为非字符串或无效 UUID 时，在数据库查找前返回认证错误。正常签名、到期时间、额外 JSON 声明、项目查找和软删除拒绝规则保持。签名/解码异常不再把库的原始文字和异常链展示给调用方。
- MCP 令牌交换归入 `app/services/mcp_token_exchange.py`，原运行时导入入口保留。令牌必须是非空、无空白/控制字符的可打印 ASCII 字符串，以 `SecretStr` 保存；只保留后续需要的 `access_token`。未知供应商附加字段不阻止接入，也不额外保存；原表单字段、接口路径及正常请求内容保持。交换增加 30 秒总超时，不盲目重试。
- 员工构造器同步使用已验证令牌；缺少地址或主体令牌时不发交换请求，认证关闭时继续返回空认证头。维持现有设备/工作流/知识库逻辑和没有 MCP 地址时不创建 MCP 工具的规则，不引入新的地址回退。错误不附带供应商地址、原异常正文及该调用的用户/会话参数，取消仍向上传播。
- MCP 及外部员工运行客户端验证成功响应必须是 JSON 对象，保留合法嵌套数据和扩展字段。错误正文、不可解析内容及传输异常改为受控错误，保留已知 HTTP 状态和对应领域异常类别。MCP `204` 仍返回空对象。正常流式片段继续原样转发，中途断连按既有资源上下文关闭响应；请求关联编号保留在调用及转发日志中。

内部兼容说明：`get_mcp_access_token` 的结果由可空字典改为 `MCPAccessToken`，项目内唯一业务调用已同步；该类型仅在 AI 服务内部使用，没有发现其他服务引用。没有核实外部 Python 扩展是否直接依赖旧返回结构，发布时需要使用同一确定版本的 AI 源码与产物。
