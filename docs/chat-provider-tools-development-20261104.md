# 聊天供应商工具协议接续开发

## 当前范围与事实（2026-11-04）

承接主计划 4.2.274，不缩减 D1～D7、微信官方渠道、多模态和 G0～G5。上一批 `866ec9b` 已发布，完整 AI 类型检查仍有 148 项问题，正式页面及真实供应商待验收。

本批处理 `ChatService` 这条文本代理接口：Anthropic/Google 的完整工具调用、调用结果历史、流式完成、轮次上限最终输出及相关资源/用量记录。另一条 Agno 员工运行链路不由这次检查代替。真实订单/物流仍暂缓，安卓员工客户端取消。

已核对本机及云端安装版本：Anthropic 0.75.0、google-genai 1.49.0；本机另有 google-generativeai 0.8.5、OpenAI 1.109.1。原 Anthropic 丢掉响应中的工具块与工具结果历史，Google 使用全局配置及旧 SDK 文本访问器；本批已替换这两个代理适配，正式发布及验收结果在下方单独登记。

## 实现与验收计划

1. 增加可选、带长度限制且不进入对象 repr 的供应商上下文。没有上下文时不增加空字段；有上下文时保留原 SDK 模型内容、签名/思考块及调用编号映射。自动循环自己回传，原始代理调用者按接口契约回传；不建立跨项目服务端全局缓存。
2. 两个供应商适配模块分别使用现有已安装 SDK；Google 改为显式凭证的请求级客户端，保留配置地址与超时。缺少凭证不回退到另一项目或全局环境密钥。SDK 客户端在正常、失败和取消时按作用域关闭。
3. 工具结果按调用编号匹配、立即跟随相应助手调用，并保留真实工具错误。上下文必须与可见助手内容/调用一致，不能把结果或供应商上下文改作系统指令；未知或错配上下文在调用供应商前拒绝。
4. Anthropic 转换 tool_use、input_json_delta、tool_result 和真实停止原因；Google 使用 GenerateContent 的原生 Content/Part，保留块边界与二进制签名，禁止 SDK 自动代执行工具。实际动作仍经过原 ToolExecutor 和上一批整批校验。
5. 核对工具选择和轮次上限后最终输出：预算耗尽后不得追加执行；最终错误、中断或多余工具调用有明确结果和终止。普通代理模式不增加自动执行。
6. 只记录 SDK 实际用量；流式用量与当前请求绑定，失败/取消不能误记成功。保留现有额度验证与库存，不通过关闭计费或模型证明取得通过。
7. TDD、SDK 模拟传输、并发凭证隔离、取消/关闭、现有聊天/工具/用量回归；完成影响分析、schema 同步、流协议和全量工程检查。模拟 HTTP 不等于真实模型或正式页面验收。

## 协议依据和当前限制

- [Claude 工具结果协议](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls)：结果按 tool_use_id 对应，工具结果不能替换成普通系统/用户指令。
- [Claude 流协议](https://platform.claude.com/docs/en/build-with-claude/streaming)：覆盖工具 JSON 增量及正常 message_stop，不能靠文本流判断整个生成已完成。
- Google 当前在线文档已主要展示 Interactions API；本项目安装的 1.49.0 适配以 SDK 的 GenerateContent、Content/Part、chats 历史和 bytes 序列化代码为准。没有据此启用服务商会话存储，也不假定当前所有模型/接口可用。[Google 文档入口](https://ai.google.dev/gemini-api/docs/function-calling)。

文档先记录计划；代码、测试、运行与目标发布各自补充真实结果。原 API/Web、CLI、权限、额度和真实业务闸门仍需分别核对。任何本批完成声明不等于全项目完成。

## 本批实现和当前验证

- 两个独立适配模块保留文本、原生工具调用及上下文，工具结果按编号匹配并使用原生结果块。失配内容、缺失/重复结果和不支持的原生动作拒绝；系统指令通过供应商的专门字段传递。Google 不再调用全局 `configure`，SDK 自动函数执行关闭，实际动作仍由原 `ToolExecutor` 负责。
- 上下文最大 512 KiB、编号最多 256 个，不进入对象 repr，没有上下文时保持原 JSON。请求输入预算包含序列化后的上下文；流式在完成帧附带上下文并由自动循环继续回传。原始代理调用者应将 `message.provider_state` 或最终 `delta.provider_state` 原样放入下一次对应助手消息；它不用于界面正文显示。
- 显式凭证与配置地址/超时按请求创建客户端，缺失密钥不回退到环境中的其他密钥。取消和失败会关闭客户端；输出不完整不执行工具，工具选择 `none` 或指定函数不能执行其他函数；轮次用尽后清除工具与强制选择，若仍收到工具调用则明确失败、不追加执行。
- 用量只取 SDK 实际数据，Google 使用实际总量减输入量以包含思考消耗；流式通过请求作用域记录，不增加旧流协议的用量字段。循环中任一轮用量缺失时整体用量保留未知，不伪造为零。
- TDD 基础上下文最初 8 失败/1 通过，供应商测试最初因模块不存在失败；缺少文本完成原因的新增测试也先失败。最终组合 **119 passed**，覆盖真实 SDK 解析的模拟 HTTP、连续工具循环、并发凭证隔离、取消/关闭、选择限制、轮次上限及原聊天/用量/预算回归。没有付费模型调用或真实客户数据。
- 本机隔离 HTTP 完成原路由 4 组验证，另有两家真实 SDK 的 6 次模拟 HTTP；额度、模型和执行器是替身，不能视为员工 CLI、真实供应商或业务验收。新模块及两份新增测试目标 lint 通过，`compileall app` 通过。
- 本机默认完整 Mypy 因资源/时限停止，完整 Flake8 仍失败。一次 `follow-imports=skip` 的受限检查出现 3 项由跳过依赖造成的类型信息缺失，也未记为通过；未改变仓库规则或屏蔽检查。随后使用本机 Mypy 1.17.1 的纯 Python 检查工具，在无网络、1 CPU/1536 MiB 的隔离容器完成默认 `mypy app`：**137 项错误、42 文件、315 个源码文件**，本批 8 个运行文件没有类型错误。Linux/生产依赖环境与此前 Windows 的 148 项不能直接当成消除 11 项的同口径比较。检查容器自动退出删除，没有安装到生产容器。
- schema 和流协议检查已列出消费者。`tgo-api` 的这条代理保留完整响应字典，当前调用者只提取文本；网页/Widget 的同名 `ChatMessage` 属于会话消息和 Agno 流，未发现这条代理的直接消费者。旧无上下文字节与 OpenAPI 字段保留测试通过，不由此替代各端真实界面验收。模型表没有变化，不增加迁移。
- `ChatService` 从 1,103 行减少到 899 行；供应商实现已拆分，剩余旧合并工具与 OpenAI 逻辑暂保留，避免在本批扩大重构。
- 原有七个本机服务按已保存归属恢复；首次 HTTP 检查失败后，直接连接复核七个入口全部 HTTP 200，没有重复启动。员工 CLI 本次实际仍返回 `No server configured`，不冒充完整员工登录态验收。
- 最终源码审查确认 8 个运行文件的 AST 与隔离默认完整类型检查时相同，之后仅做格式整理；12 个源码/测试文件相对当前提交新增 lint 为 0。原 `ChatService` 的 lint 从 80 项减至 50 项、计量模块 4 项减至 0，旧 schema 的 27 项和旧计量测试的 2 项仍保留。没有把全部工程检查记为通过。

目标云端入口为 https://kf.changzubao.top；本批没有新增页面布局，现有 AI 员工、工作流、设备配置入口保持原风格。正式供应商、Ego 登录后操作、订单/物流和原 G0～G5 仍按各自门槛验收。
