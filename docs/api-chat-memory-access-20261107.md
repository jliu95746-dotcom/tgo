## 解决的问题与范围

`DELETE /v1/chat/memory` 原先只检查员工具有发送权限，未按当前聊天频道核对企业归属和接待范围。现在复用已有频道与员工资料访问检查：

- 读取 IM 消息位置前，核对原员工、原令牌、企业及当前发送权限，同时验证访客、员工、企业群或 AI 员工频道归属。其他企业和已删除访客被拒绝；按现有接待范围受限的普通员工不能清除转接后不再归其负责的访客，管理员仍沿用原企业内管理规则。
- 等待 IM 位置、AI 清除结果后重新核对；AI 员工归属查询本身也是远端等待，其返回后再次核对员工身份。账号停用、令牌版本、角色、企业、删除状态及发送权限变化均不能继续后续操作。
- 查询既有清除记录时加入企业范围；移除消息位置和数据库对象调试输出。通知失败保留固定告警，不输出异常原文。
- 保留合法会话的会话编号、清除位置、重复更新、无历史记录及通知目标语义。管理员及具有发送权限的普通员工，在五类自有频道上均有回归。

同期校准图片/语音输入的明确类型、拟人技能空值、文件响应注解和原生近期对话的只读接口；记忆记录两字段改用正确 ORM 类型，并同步去掉聊天记录及交接摘要中两处冗余转换。共六份运行源码及一份新测试；没有恢复未挂载的旧 MCP 路由或新增其他业务入口。
