# 员工详情归属契约与知识评审恢复

## 目标与已确认缺口

接续 4.2.277 的实际 Ego 云端验收。知识能力状态、员工测试问题与知识评审出现 404；错误为“未找到当前企业的 AI 员工”。API 路由已注册，当前员工在列表可见，不能将问题归结为缺少前端页面或直接跳过归属检查。

源码表明 `tgo-api.agent_knowledge_cases._agent` 要求远端员工编号、企业编号同时匹配，而 `tgo-ai.AgentResponse/AgentWithDetails` 未声明 `project_id`，实际详情序列化会丢弃 ORM 已有的企业编号。本批补齐服务端响应契约，保留缺失/异企业/异员工的原拒绝逻辑。

1. 先验证基础/详情响应 JSON 与实际注册详情路由的输出；响应企业编号必须来自服务端员工记录，不从请求参数补值，缺失/空值/错误 UUID 拒绝。

3. 运行 AI 响应/员工及 API 归属/目录/能力/评审回归、完整默认工程和同步检查；以隔离候选及真实 HTTP 验证响应与原网关校验，再提交推送及限定发布。
4. 发布后在原 Ego 空间 0/p1 的云端登录态实际检查测试问题、能力状态和评审恢复，不自动通过评审、切换员工或把旧报告当成本轮真实模型验收。

原 D1～D7、官方微信、多模态和 G0～G5 全范围保持；真实订单/物流继续暂缓，安卓员工客户端取消。工程检查、合成契约、正式页面和真实业务分别记载。
