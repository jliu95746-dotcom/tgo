## 实现及使用边界

1. 在现有“我的审批”内增加“待核验流程”。仅返回当前企业、原确认人的中断任务，支持分页和刷新。详情紧跟所选任务展开并接收键盘焦点，沿用原紫色操作按钮和深浅主题。
2. 核验时重新获取摘要与运行详情，核对运行、流程、节点回执及状态。详情变化时隐藏不匹配正文并禁止继续；无法取得详情仍允许停止。正文用 Markdown 展示，不加载外部图片或链接。
3. 恢复执行的成功回执和加密游标在同一事务保存；下一步开始前仍保留持久动作意图。密文绑定企业、原审批、原定义、原输入、已有上下文和每条回执摘要，禁止客户端提供执行结果。
4. 只有审批后所有步骤均有完成回执，且与加密游标完全相符，才允许继续。缺结果、改动、密钥不可用或恢复位置缺失均拒绝继续。已开始但结果不明的操作保留核验，可停止本次流程；停止不会撤销已经发生的外部操作。
5. 核验提交先重新验证原确认人的企业权限，再锁定原运行和审批，比较当前摘要。相同决定可重复查询，不同决定冲突；返回丢失时界面查询原回执，不自动再次提交决定。
6. 审计只保存摘要、决定、人和时间等元数据，不复制客户正文或恢复明文。再次中断保留先前决定并递增批次；最多保留 256 个决定，达到继续上限后仍留最后一次停止位置。终止后清理加密恢复正文，保留决定历史。
7. 接续使用 `encrypted_verified_resume` 标记，密文与原批准保持。已部署的旧 Worker 对该标记失败关闭，不会回到原批准位置重放；新版必须核对原确认人的核验授权、游标摘要及当前回执。

接口由 API 使用登录员工身份代理，Workflow 内部接口仍要求内部服务密钥；公开摘要不含密文、可执行检查点和节点输入输出。API、Workflow、Web 三层类型和错误边界已同步。
