## 问题与修改

`/v1/store/proxy/{path}` 将 GET、POST、PUT、DELETE、PATCH 注册为一个多方法路由，生成的 OpenAPI 为五种方法分配相同 operationId，且编号随 Python hash seed 改变。这影响接口描述和自动客户端生成；没有证据将其计为五个线上业务故障。

现在五种方法各自声明路由，仍调用同一个处理函数，沿用相同路径、员工鉴权和转发逻辑。补充原 `Response` 返回注解。AST 核对确认处理函数正文及其余模块内容未变，没有改业务字段、数据库、迁移、依赖或检查规则。现有前端 `storeApi.ts` 使用固定路径与方法，无需随接口编号修改；使用 OpenAPI 生成的外部客户端应重新生成相应方法。
