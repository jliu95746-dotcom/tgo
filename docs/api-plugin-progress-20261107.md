## 问题与实现

插件安装与升级原先逐行重建SSE进度流，会改变事件边界和换行；代理连接/读取异常的原文同时写入日志和发给页面。插件日志接口在运行器返回不存在时直接返回空值，也不能提供明确的404。

- 安装和升级复用 `plugin_progress.py`，按字节转发有效进度流，保留原事件边界、CRLF、注释、事件字段及分片中的中文。继续使用原POST地址、载荷和企业范围，不跟随重定向，不重发安装或升级。
- 连接、写入和连接池等待使用原配置超时；进度读取保留长连接，避免把较长构建阶段切断。非200状态保留原固定状态提示；200但没有正确进度类型的响应返回固定失败事件，不转发错误页或JSON正文。
- API代理自身异常只记录错误类型并发送固定失败提示，不记录或发送异常原文。取消消费时释放HTTP连接；不伪造完成事件。
- 日志不存在返回404，正常日志、空日志及空对象保持。启动仍允许不发送临时配置，让运行器读取已经保存的配置；停止、重启、卸载及其原成功/400失败约定保持。同步校准相关返回和可空输入类型，没有新增业务字段。

本批五份源码及测试文件，未修改运行器、前端、模型、数据库、依赖、检查配置或其他Worktree。运行器原代码已核对：启动的可空配置会读取持久化记录，安装/升级使用含`stage`、`message`的单行JSON事件；现有前端使用流式UTF-8解码并消费这些字段。
