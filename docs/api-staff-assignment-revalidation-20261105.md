## 运行行为

1. 请求前重新读取当前项目的持久化分配规则，确认启用，并沿用上一批的可用供应商与模型解析。保存规则/供应商编号、更新时间、明确模型、实际模型和实际系统提示词的不可变快照。
2. 不在等待外部 AI HTTP 时新增配置行锁。模型成功返回或抛出普通错误后，都先按供应商、规则的顺序重新查询并加共享行锁，确认资源状态及版本仍一致。请求取消继续传播，不转换成负载分配。
3. 供应商停用、软删除、实际删除，规则停用、删除、更换供应商、模型、提示词或服务时间，以及先关闭再重新打开的变化，均丢弃旧生成结果。内部返回刷新标记，调用方重新读取当前规则、服务时间与可用客服，按负载分配，不再发起第二次 AI 请求。
4. 变化后当前不在服务时间时，不分配人员，保留排队、人工模式和可重试状态；模型原文和原理由不写入该条历史。
5. 保存分配历史前，再读取原规则。规则已删除时历史不引用旧外键；规则仍存在时保持短暂共享锁到所属事务提交，避免校验后、写入前又变更现有配置行。

`model_used`、`prompt_used` 仍表示这次实际尝试的请求，而非重新选择后的配置或生成成功；受控失败原因和生成结果分别保存。没有修改既有历史。更新时间检查采用保守策略，即使只是供应商名称等元数据变化，也会丢弃本次旧结果，使用当前候选负载分配。
