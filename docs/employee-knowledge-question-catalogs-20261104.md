# AI 员工企业测试问题与版本

日期：2026-11-04。主要业务验收环境为 `https://kf.changzubao.top`，本机只用于开发、隔离验证和排错。整体 D1～D7 及原 G0～G5 继续推进，本批不代表全部目标完成。

## 本批解决的问题

云端“域见企微客服”试聊仍显示女包问题；输入企业服务问题能够回答，却因不属于固定目录而无法进入岗位评审。现增加“员工测试问题 → 配置测试问题”，管理员可以为同一企业的不同员工分别配置六个业务问题。保持原界面样式，系统管理的模型和资源无需重复填写。

咨询和售后各三题：前两题要求有资料依据，第三题核对资料不足时拒绝未核实承诺。预期行为由服务端决定，客户端只能填写问题，不能伪造项目、管理员、评审结论或放行规则。

## 版本、评审与启用

- API 新增 `api_agent_knowledge_catalogs`，迁移为 `0081_agent_knowledge_catalogs`，父版本 `0080_merge_customer_turns`。员工 ID 为跨服务逻辑标识，运行时通过现有 AI HTTP 客户端核对归属，不直接读取 AI 数据库。
- 每次保存创建不可变版本。按企业、员工和版本唯一；请求键按企业和管理员唯一。稳定项目行锁保护首次写入及并发版本检查，过时保存返回 `409`。同一请求重试返回原回执；若期间已有更新，原回执注明已非当前版本。
- 六题的用例 ID 绑定该版本，原版本和评审保留。新版本只接受版本生效后开始的试聊，旧成功记录不能直接转换为新版本通过。未配置的员工继续保留原 v1 用例，避免原地改写历史。
- API 向 AI 传入可信当前目录，过时用例不能新建评审；历史请求重试仍能找回原评审，但其 `case_status=changed / effective=false`。读取期间问题版本发生变化时要求刷新，不能恢复旧通过状态。
- 岗位启用检查和执行前复核携带员工 ID，并读取该员工当前问题。知识用例的版本变化会改变启用要求摘要，管理员需重新确认要求和测试；保存问题不会直接启用、停用或切换接待员工。
- 为存量记录兼容，旧用例及评审请求计算摘要时省略空的新增生效时间字段，旧启用要求摘要也保留原算法内容；新增字段不能让所有旧评审无故失效。

## 前端行为

编辑状态按当前项目、管理员和员工隔离。登录身份、项目或管理员角色变化时清除草稿并中止旧请求，迟到回执不能覆盖新身份的状态。网络结果未知时冻结编辑并重试原请求键；并发冲突要求重新读取，不静默覆盖。保存后刷新预设问题和评审目录。
