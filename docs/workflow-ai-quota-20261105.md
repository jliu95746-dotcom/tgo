## 当前实现

- 调用改为 Workflow → API 私有额度入口 → AI，复用现有 HTTP 客户端。API 从 Workflow 私有接口读取真实运行、已保存的节点快照、员工编号、固定设备策略及额度归属，不信任调用正文携带的归属。
- 后台手工运行的操作人员编号和登录版本由 API 鉴权后传入；Workflow 持久化这些私有引用，普通运行记录不返回。API 在申请额度和实际模型授权时核对当前人员权限、企业和登录版本。
- 同一独立工作流的多个 AI 节点共用一次预约；客户回复内嵌流程借用原回复的预约与租约，不能自行结算或另扣一次。已纳入计费的企业不能使用未计量来源；原未计费企业保留原有兼容语义。
- 每个节点调用先保存请求摘要和提交状态。同一节点重复调用、变更输入、旧租约和结果未知均不能自动重新生成；成功回执仅保存 AI 执行编号，不复制问题、回答或服务凭据到用量记录。
- 独立工作流由原运行结果结算。明确失败且无可领取回答、无未知调用时释放一次；已完成并保存在原记录中的回答只结算一次，即使后续步骤取消。超时、缺失或不一致且无可领取回答的回执保留待核验。普通清理任务不得直接释放工作流预约。审批等待与恢复沿用同一预约，恢复前核对当前运行、人员、并发限制并换发租约。
- 新增 Workflow 迁移 `0023_workflow_ai_usage_owner`，只增加可空私有引用列；已有历史不回填来源。存在真实归属记录时阻止直接降级删除列。代码回退可保留新增列；数据库恢复必须使用发布前备份，不能以代码回退替代。
- 节点错误仅展示预定义安全提示，区分额度不足、授权变化、重复/待核验与连接问题；不透传上游错误正文。
