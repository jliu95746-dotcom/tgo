## 具体行为

1. `RAGServiceClient` 保留原业务方法，传输职责抽到同服务 `rag_transport.py`，沿用原配置、超时、计费请求头和 HTTP 客户端。对象、查询及重复文件部分有明确类型，不使用 `Any` 或类型忽略掩盖问题。
2. 预期对象的接口收到成功状态但内容为数组、标量、空值或非 JSON 时，返回受控 502；分页字段存在但不是对象时同样受控失败。正常对象保持，原 `has_previous`→`has_prev` 转换继续。
3. 原上游错误状态及响应详情继续传递；日志移除完整 URL、查询值、响应正文和网络异常原文，保留请求编号、状态、耗时和错误类型。取消继续传播，不新增自动重试。
4. `delete_collection`、`delete_file` 按原声明及 API 调用方式返回空结果。下载仍返回缓冲的原始 HTTP 响应，包含状态、字节和响应头，没有改为流式下载。
5. 快速上手的知识库检查先确认分页及数值结构，再判断是否完成；正常正数判断保持。缺少数量或异常数据返回未完成，意外异常只记录类型。

38 个业务方法的 `_make_request` 调用经 AST 比较完全相同，项目范围、路径、JSON、表单和查询参数未变。没有改变知识审核门禁、自动回答渠道或扩大自动回复范围。受控服务不能证明真实资料检索或第三方模型效果。
