# 正式聊天流的空闲保活与关闭清理

## 原始目标和实际入口

保持完整开发文档、D1～D7 和 G0～G5 的范围。上一批预留远程实现没有启用，本批转向正式使用的 `SupervisorRuntimeService.stream → create_sse_response → SSEHandler`；不把预留实现或健康检查当作真实业务验收。

## 已取得证据

原实现新增七项回归均失败：异步生成器在 GeneratorExit 时仍输出 disconnected，取消等候被输出覆盖；空闲连接的心跳任务只等待不发送；缓冲/队列异常把原文写入公开帧及日志；直接关闭响应迭代器或发送响应头失败时，没有完整释放事件注册。复现使用实际 SSE 响应类和事件器，不调用真实模型或业务系统。

## 实施和验收

1. 心跳在原事件循环中输出标准 SSE 注释，不伪造业务事件或最终结果；终态和历史缓冲仍只输出一次。
2. 取消与 GeneratorExit 原样传播，关闭清理中不再 yield。普通异常保留原 error 事件形状，返回固定提示，日志只记录异常类型。
3. 响应迭代结束、取消、发送失败和原后台清理统一进入可重复调用的清理，保持原执行任务的停止/完成所有权。
4. 运行新增 TDD、原 SSE/员工/设备/回复生命周期回归、真实回环 HTTP 的读取/空闲/断开检查、完整工程和消费者兼容检查；提交推送后按备份恢复、隔离候选和回退流程发布。

本机 API/AI 本轮已直接核对 HTTP 200。Ego 的实际云端检查见下文，未把连通或健康状态当作业务通过。真实订单/物流仍暂缓，安卓员工客户端取消。

实现、工程检查、合成 HTTP、正式页面、真实供应商和发布分别记录。

## 实现与实际验证

- 原始八项复现全部失败后修复。移除只等待但不发送的心跳任务，在消费循环中使用生产默认 30 秒间隔输出 `: heartbeat` 注释；原 domain 事件、时间戳/UUID 编码及单次终态保持。API 现有 SSE parser 会跳过注释，该核查不代替每个渠道的真实验收。
- `stream_events` 清理中不再输出消息，取消和 GeneratorExit 原样传播，正常结束仍发送 disconnected。传输/序列化异常使用固定中文错误及异常类型日志；该范围不等于上游所有业务异常已完成隐私审计。
- 响应原生 ASGI 生命周期与迭代器 finally 共享可重复调用的清理，覆盖响应头发送失败、正常结束、断开与未开始迭代的情况。原 `own_execution` 现在委托原响应的 ASGI 行为，并保留封装后修改的状态、headers、body 和 background；执行任务仍由原 owner 取消和等待，不新增接管机制。
- 首轮八项修复连同原 SSE 回归 13 passed；中间新增当前响应状态传递用例先失败，再修正 body/background 传递。最终与聊天、设备调试、取消和回复生命周期组合 **94 passed / 58 warnings**，类型变量命名修正后 SSE 再验 **14 passed**，各组重合，不累加。
- 实际启动本机 TCP HTTP 服务，使用原生响应和执行 owner 完成正常结束、默认 30 秒保活、固定错误与客户断开四组场景；4 次真实 HTTP、4 次结束回调、0 次模型请求，最终事件注册数 0。它是隔离组件验证，不是登录用户/实际供应商或真实渠道验收。
- 完整默认云端 `mypy app` 最终为 **112 errors / 40 files / 319 source files**；较上批 116 项诊断按源码行指纹比对消除 4、引入 0。首轮新增变量复用导致的两项诊断已经修正，未降级导入检查；两个检查源码 AST 与当前运行源码匹配。完整语法检查通过，完整 Flake8 仍失败，本批两个运行文件及新测试新增 lint 为 0。无模型/迁移或公开 DTO 变更，流消费者技能清单已复核。
