## 保存修复

- 原大 store 仅抽离保存动作，不扩大为其他模块重构。同一身份、编辑器和工作流的进行中保存共用一个 Promise；“保存并填写问题”和“运行”会等待同一次保存。
- 保存期间的新名称、节点及连线保留为未保存状态，同时使用已确认的新版本；不能把保存开始后的输入覆盖掉或标记为已保存。
- 登录身份、企业、角色或编辑页面已变时，迟到回执被拒绝，不替换新编辑器，也不让旧测试继续。其他工作流或未推进版本的回执不能清除未保存状态。
- 网络结果未知不自动重试；原请求失败后清理进行中状态，显式重试仍携带原预期版本，由服务端核验。列表刷新失败不将已确认保存改判失败。
- 无后端、数据库迁移、接口字段或消息协议变化，原页面风格保留。
