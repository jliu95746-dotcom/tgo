## 实现与保持项

1. **创建与编辑采用相同知识库核验。** 原创建路径会直接保存传入的知识库编号，编辑路径已有归属检查。现在创建也在写入员工和关联记录前调用既有核验方法。隔离 SQLite 用例验证：缺失、返回未交代请求编号、返回其他编号或连接失败时，不新增员工或关联，也不改动原员工名称和知识库；合法绑定仍可保存，员工保持未启用。
2. **知识库结果完整对应请求。** 已找到及未找到集合必须共同覆盖请求编号，不能交叉或多出编号；找到的记录不得重复。比较使用 UUID，不改变请求中的合法 UUID 写法、返回顺序及元数据。依照当前 RAG 服务实现，保留重复请求以及对应重复缺失结果；404 继续返回明确的缺失列表，不把不完整的 200 空返回当作核验成功。
3. **工作流结果限定请求范围。** 返回必须是合法记录列表，不得出现重复或未请求的工作流。保留查询部分结果的行为；原有员工关联和固定发布版本核验继续要求所选工作流完整可用。本批不修改固定版本解析、停用或撤销规则。
4. **批量查询错误边界。** 非预期成功状态、无效 JSON、错误结果形状及 HTTP 错误转为服务现有异常类型；连接与超时错误不再把原始异常文字放进资源编号。422 正文不再直接回传；缺失资源通过 `missing_ids` 明确表达，保留资源错误类别。没有修改 RAG 搜索、可用性或嵌入配置同步的其余错误路径，不能据本批认定所有 RAG 客户端路径完成。

语法树审查确认：11 个数据模型定义、6 个 HTTP 请求调用点保持；除本阶段指定的方法外，其他函数保持。创建方法移除新增核验块后与原方法一致，原数据库写入、锁和默认状态处理未改。公开路由、Schema、数据库模型和迁移没有修改。既有大体积员工服务仅增加这项核验，复用原方法，没有夹带拆分或重构。
