## 修正及需求依据

1. **显式导入共享测试数据。** 七个消费者移除对 `pytest_plugins` 导入顺序的依赖，显式引用既有 `setup` 或设备测试数据及其依赖。没有重写权限检查、审批、撤销和执行结果断言。设备测试单独或调整收集顺序时可正确解析依赖；仍须在指定 PostgreSQL 环境实际执行。
2. **旧员工配置摘要的测试快照。** 原测试的“旧数据”由当前模型导出，误带历史不存在的空 `device_script_selection`。依照当前配置摘要实现及既有设备选择兼容测试，排除这个可选字段，继续严格比较摘要，并保留绑定新增、版本变化使摘要变化的断言。没有修改摘要算法或失效保护。
3. **客户资料及会员只读能力。** 总计划第 12 节包含客户/会员只读工具，当前显式绑定契约也允许这两类能力。将“完全不暴露能力”的旧预期校准为：只暴露明确配置的操作和对应当前测试证据，但连接保持关闭、证据及连接均 `can_enable=false`。原客户信息不得落入回执的断言保留；配置测试不会自行授予启用权限。
4. **IM 注册测试隔离。** 将真实权限复核所用的新数据库会话指向已有隔离测试库；继续执行当前平台、访客身份及凭证核验，没有替换或关闭权限检查。
5. **额度恢复测试边界。** 本用例测试 IM 回执查询失败时继续保留额度、延后复核；将独立的员工试聊/工作流扫描替换为本用例的异步测试替身，并核对两项扫描均被调用。IM 查询失败、状态、时效及额度原断言保留。员工试聊、工作流扫描本身继续由各自测试及 API 全量覆盖，真实 PostgreSQL 恢复不据此认定完成。

语法树审查核对：原断言均保留，只有旧的“操作与证据都为空”合并断言按最新只读能力契约替换；新增对应证据、有效期及禁止启用断言。配置摘要断言语句保持，旧数据构造的上述变化单独说明。
