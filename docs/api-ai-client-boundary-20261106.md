## 实现

1. 既有 `AIServiceClient` 的 HTTP、序列化及 JSON 处理抽到同服务 `ai_transport.py`。请求参数具有明确类型，保留原 URL 配置、超时、`trust_env=False`、服务身份、持久计费许可和 JSON/原始技能文本/媒体 multipart 三种传输。
2. 对象接口收到错误结构或非 JSON 成功响应时受控 502；工具/技能集合检查每项对象结构，不部分返回。督导的历史文本成功响应仍包装到 `content`，直接 SDK 的 SSE 解析仍支持原多行、注释、普通文本与末尾事件。
3. 修复流式错误分支错误地 `await response.json()` 的实际问题：先读取响应，再同步解析 JSON。正常 JSON 错误详情与原状态继续传递；非 JSON 错误正文使用固定提示。SDK 的流式日志移除 URL、上游正文及网络异常原文，保留请求编号、状态和异常类型；员工存在检查与快速上手的异常日志也不再记录原始异常内容。
4. 对话控制层明确拒绝非对象事件，并关闭源生成器，保留既有阶段、取消和终止处理。没有把异常数据自动转成成功回复。
5. 员工列表在关联设备前检查对象条目；快速上手和默认员工选择使用同一个集合检查。员工名称、风格名称和频道显示字段使用相应文本类型；损坏的模型引用元数据返回 503，继续阻止删除。工具更新及前缀移除检查本次使用的名称/ID 类型。
6. 调用方协议和 JSON 返回声明同步收窄；工具、技能端点使用既有响应模型的 `model_validate`，公开字段和模型保持。声明无返回值的方法完成错误校验后返回空值，原 204 行为保持；没有扩展 API 业务能力。

客户端除四个迁出方法外，其余 98 个方法保留，其中 51 个直接 `_make_request` 方法的调用 AST 全部一致，项目、路径、查询、JSON、文件及额外请求头未改变。大客户端已分离通用传输，现有岗位/设备代理继续保留，仍需在后续相关变更时评估职责大小。

## 环境、证据与限制

本机服务状态 Skill 确认基础设施、API、AI 和可选服务未启动。测试使用原虚拟环境、受控 HTTPX、ASGI、SQLite 和临时回环 HTTP；服务脚本结束时关闭。没有新界面、页面预览或运行中的应用入口。本批没有进行员工/访客 CLI、Linux 容器、真实 Provider/计费、正式全栈或 Ego 域名验收。

HTTP 对比只使用合成身份、许可、媒体和回环地址，不连接生产数据库或真实模型，不产生实际账单。没有重新读取云端版本、健康或变更生产服务，不能把此前云端核验时间写成本轮结果。导入时既有 bcrypt 版本警告保留，HTTP 命令退出 0、断言及输出文件完成。

同步 Skill 没有检测到 schema 字段或按文件名匹配的流式变化；本批手动核对实际 SDK、控制层、调用方及上述流式测试，不能以脚本无命中认定协议通过。PR 摘要 Skill 返回 1、仅标题；实际 Git 范围和差异另行复核，未修改 Skill。
