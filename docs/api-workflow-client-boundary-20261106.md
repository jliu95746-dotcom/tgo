## 行为变化

1. 在既有 `WorkflowServiceClient` 内抽出同服务的 `workflow_transport.py`，统一声明 JSON 对象、查询值和流式返回类型；原配置、鉴权请求头、超时、`trust_env=False`、原始签名字节及重复查询参数保持。不增加重试。
2. 预期对象的接口收到数组、标量、空值或非 JSON 成功响应时，受控返回 502；预期列表的接口检查列表及每项对象结构，不部分返回。具体业务 DTO 的字段校验仍沿用原模型，不声称已治理所有异常响应。
3. 保留正常 JSON 错误详情和原 HTTP 错误状态；非 JSON 错误正文改为固定提示，避免透传内部页面或业务内容。流式拒绝仍在开始输出前返回原状态，正常 SSE 帧及员工身份头保持。
4. SDK 自身日志移除完整地址、查询参数及原始网络异常，保留请求编号、方法、状态、耗时和异常类型。此次测试只覆盖该 SDK 日志，不代表所有 HTTP 客户端、历史日志或全系统隐私检查完成。
5. 意图路由调用方只读返回注解改为 `Mapping`；移除注解后的执行 AST 相同。用量结果仍通过相同模型和相同字段校验，未修改可用回答条件。

客户端原 59 个方法中三个传输方法移至基类，业务入口保留。去除注解并统一新响应检查调用后，54 个剩余方法的执行结构一致；差异只余流式错误处理和用量结果的模型调用形式，均有回归测试。客户端整理后仍超过 800 行，已按传输职责拆分；本批不继续拆分各业务代理或引入第二套 SDK。
