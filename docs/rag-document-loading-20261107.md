## 本阶段实现

- 原实现把文件名用作目录匹配规则。合成用例证实，`资料[01].txt`、`规格[甲乙].md` 可能未读指定文件，转而匹配同目录的其他文件。现在通过既有 LangChain GenericLoader 与单文件 BlobLoader，直接读取指定路径，不再把名称解释为匹配规则。
- 工厂拒绝目录和不存在的文件；指定路径在延迟加载前已被删除或变成目录时明确失败，不退回目录遍历。普通名称、中文、空格、相对路径及方括号名称均验证了实际正文和来源信息。
- 保留 PDF、纯文本、Markdown、HTML 的解析器，以及 Word 先用 Unstructured、仅 DOCX 可回退到 Docx2txt 的原有顺序。未知类型原来会因 MIME 解析器缺少必填参数而进入 TextParser，现在直接沿用这项实际回退行为；没有扩展上传格式白名单。解析器说明同步改为实际选择的名称。
- 读取器日志不写原始路径、文件名、任意 MIME 原文或异常正文；构造失败的 `message` 使用固定内容，内部仍保留原异常及因果链。停止和取消信号继续向上传递。**没有把这项局部修正记为全部日志及错误序列化脱敏完成。**
- 加载器返回既有协议，解析器返回 SDK 的 BaseBlobParser；错误详情改用明确字段的 TypedDict。错误辅助模块除类型声明、注解与排版之外的执行结构保持，原序列化字段及内容没有改变。
- 声明并锁定 **pdfminer-six 20260107**，解决实际 PDF 解析缺包。官方来源和文件摘要见 [PyPI 版本页](https://pypi.org/project/pdfminer.six/20260107/)；下载文件 SHA-256 已核对。没有安装庞大的全部文档解析扩展或升级现有运行包。

本批共 **5 文件：2 份运行源码、1 份新测试、pyproject.toml 和 poetry.lock**。另外 **85 份运行源码字节内容保持**。新测试此前受既有 `test_*.py` 忽略规则影响，经过检查后明确加入 Git，没有全量暂存或调整忽略规则。
