# 远程 AI 员工工具执行补齐

## 范围与当前证据

接续 4.2.275，保留 D1～D7、微信官方渠道、多模态和 G0～G5 全范围。真实订单/物流仍暂缓，安卓客户端取消。

本批定位到另一条 Agno 远程员工路径：运行构建器直接赋值 SDK 只读 `id/name`；本地工具执行绕过原 Function 钩子和确认要求，并打印完整参数、结果和异常；远程流没有严格核对最终事件、原运行、会话和重复调用。

新增 19 项复现全部失败，包含真实 SDK RemoteAgent 的构建、确认/用户输入/外部执行门槛、整批编号与参数、原生钩子、隐私输出、运行/会话检查、重放和流结束。不是实际店铺或付费模型测试。

## 实施和验证计划

1. 保留远程服务的真实 agent_id，通过明确方法绑定本企业员工编号、名称和最小追踪元数据，不再修改 SDK 只读属性。
2. 独立本地工具执行模块：先检查完整批次，未授权/不可调用的成员使本批不执行；远端的 confirmed/answered 不能代替本地人工授权。保留 Function 前后和环绕钩子，通过 SDK 公共执行入口调用，钩子失败不能放行。关闭本路径新引入的 SDK 磁盘结果缓存，沿用原直调用不写缓存的行为。
3. 不记录参数、结果或完整异常；只保留固定错误和类型。取消及混合取消异常保持向上传播，执行前后重新检查当前员工执行作用域。
4. 独立运行接续模块：原运行/会话不变化、同一编号不重复执行、十轮后明确停止。流式仅在原流完整结束后处理暂停请求，最终事件先核对再发出，错误/取消/中断不执行工具。
5. 运行 TDD、原 MCP/当前知识/员工执行回归、真实 SDK 模拟 HTTP、完整工程与目标检查，恢复本机服务；代码审查、提交/推送后再按备份恢复、隔离候选和回退流程发布。

本机七个已核对归属的项目服务暂时停止用于受限内存测试，云端不受影响，结束后按原记录恢复。Ego 复查仍只有用户空间 0，不能把其浏览器清单视为正式页面验收。

实现、检查、发布和真实业务分别登记；原型、替身或健康状态不能替代正式验收。

## 当前实现和本机验证

- 已拆出 `store_remote_agent.py`、`remote_run.py`、`remote_tool_execution.py` 与内部请求 DTO；旧构建器保留显式导出。远端 endpoint 仍用远程员工编号，本地事件使用企业员工编号，不再给 SDK 只读属性赋值。原大文件本轮只抽出相关类，不顺带重构其他模型/工具逻辑。
- 本地执行使用 `FunctionCall.aexecute()`，保留原 Function 前后和环绕钩子。先检查整个待执行批次，拒绝错误编号、非有限 JSON、重复调用与本地未授权能力；需要人工确认、用户输入或另一层外部执行的工具停止，不把远端 confirmed/answered 当作本地批准。
- 取消和当前员工执行权限撤销向上传播；入口前后及远程接续边界重新检查。钩子里发生权限撤销也不能继续动作。隐藏参数、结果和原异常日志；MCP 认证只在工具结果返回经过校验的 HTTP(S) 登录链接，不记录该链接。
- 原生 SDK 模拟 HTTP 曾复现接续丢失 `auth_token/user_id`，现以单次运行闭包保留，不写入共享员工或 client 状态。保持原 API Key、Bearer token、user/session；首次由服务器分配的 session 继续沿用。仅完整、同一运行的暂停请求允许执行；禁止重放、终止后追加事件和无最终事件的流；十轮后明确停止。
- 初始 19 项复现全部失败后修正，十个测试文件组合最终 **229 passed / 45 warnings**；中间的 227 项与 126 项回归有重合，不累计。补充两个配置用例首次因测试装配漏传 settings 而失败，修正测试后通过，不把该装配错误写成产品缺陷复现。完整语法检查通过，完整 Flake8 仍有历史问题，8 个修改源码/测试文件逐行比对新增 lint 为 0。未把完整 lint 记作通过。
- 独立进程启动真实 TCP 回环 HTTP 服务，使用实际安装的 Agno 2.3.23、httpx 0.28.1、Pydantic 2.11.7 完成流式/非流式接续、流截断、重复调用及确认门槛五组场景：8 次回环请求、3 次合成工具动作、0 次真实供应商请求。原生 hook 顺序、凭据、会话、最终编号均已核对。该结果不代表真实店铺或订单验收。
- 本批仅 tgo-ai 的 6 个运行源码，不改数据库模型，不需要 Alembic 迁移；内部 DTO 不增加公开 API 字段。schema/流式技能脚本的默认路径检测未覆盖新增未跟踪文件及无 stream 字样的 helper，已另外显式核查内部 DTO 和原生事件、上游 runner；API/Web/Widget 的公开 SSE 结构保持。

## 验收边界

本批的重放防护是单次运行范围，不是跨请求的持久幂等。已执行的工具不宣称自动回滚。需要人工确认的远程工具暂停等待适配，不伪造已完成的人审恢复基础设施。无实际远程店铺服务、供应商、官方渠道及登录后页面验收；当前接待员工不自动切换或启用。真实订单/物流继续暂缓。

进一步核对实际调用入口：`AgentBuilder.build_agent` 中远程分支原本被注释，默认仍走本地员工；治理试聊也明确拒绝远程员工。本批保留这些状态，修复的是预留远程实现及其身份绑定边界，不能声称正式页面已经能创建、验证并启用远程员工。身份构建用例使用实际 SDK 类，但上层构建结果为测试注入，未覆盖尚未开放的默认入口。

完整默认 Mypy 首轮得到 121 项错误，发现本批 5 项：SDK 方法签名与两个可空配置。已补齐流式/非流式重载和请求凭据，并在取凭据前拒绝缺失远程配置。Agno 2.3.23 的 `BaseRemote.arun` 静态返回类型与其 `RemoteAgent` 实际协程行为冲突，使用带版本说明的单点 `ignore[override]` 保持真实可等待返回类型；没有全局关闭类型检查。原生 SDK 双路径模拟 HTTP 与真实回环 HTTP 均继续验证实际返回和凭据。
