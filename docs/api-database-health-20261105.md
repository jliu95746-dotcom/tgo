## 修正内容

- 数据库健康辅助函数使用 SQLAlchemy 2 的 `text("SELECT 1")`，修正原始字符串导致检查返回 False 的问题。
- 初始化辅助函数通过现有 `app.models` 注册完整模型，移除对已不存在的 `assignment` 模块的引用。真实 PostgreSQL 中完成两次初始化，并核验项目、员工和两类分配表存在。
- 同步、异步会话及健康辅助函数的异常日志只记录异常类型；原异常继续抛出，会话回滚和关闭行为保留。
- 同步和异步 SQLAlchemy 引擎启用 `hide_parameters=True`，隐藏 ORM 格式化异常中的绑定参数；补齐现有连接事件函数的类型标注。

当前 `app/` 内未找到 `init_db()` 或 `check_db_health()` 的调用方，因此这两个辅助函数的错误不能计作已确认的线上功能故障，也没有把它们临时接入现有健康接口。实际使用的会话依赖和全局引擎属于本批影响范围。

`hide_parameters` 不会删除异常对象的 `params`，也不能保证隐藏 SQL 字面量、数据库驱动 DETAIL 或其他调用方自行记录的内容。本批通过不等于全项目“严重隐私泄漏 0”的最终验收。
