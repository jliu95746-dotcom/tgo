## 范围与实际问题

本批对应共享资源连接和 P8 凭证、日志保护。检查发现商店客户端会记录 HTTP 错误正文和异常原文；绑定、获取模型及代理接口还会把异常文字返回页面。异常中若带有令牌、上游正文或含凭证的 URL，就可能泄露。

凭证响应原来直接以字典下标读取；缺字段、空白字符串、错误类型可能造成未处理异常、数据库错误或覆盖旧值。模型详情虽然已有 Schema 校验，异常内容仍可能外露，关键标识空白也未拒绝。

## 已完成的行为

1. 四个商店调用统一校验 JSON 对象响应。空正文、HTML、数组、标量等异常成功响应受控拒绝；HTTP 错误保留原错误类型和状态。
2. 绑定响应先核验 `user_id`、`email`、`api_key` 三个非空白字符串，再进行本地凭证查询和保存。非法响应不会创建凭证或修改已保存的密文、账号及邮箱。
3. 模型详情继续沿用现有 Schema，同时拒绝空白模型和提供商标识；校验错误使用固定说明，不透出原始输入。
4. 客户端记录状态码或错误类型；商店绑定、模型获取、代理异常及卸载后台记录不再拼接原始异常。公开的正常代理正文继续透明转发，这不是对整个代理响应进行脱敏。
5. 保留现有方法、URL、请求头、超时、代理环境行为及重定向策略；没有增加重试。安装、卸载的远端记录仍按现有尽力记录方式处理，记录失败不改成撤销本地安装或卸载。
6. 卸载同步传递已存在的资源编号，类型与实际数据库筛选一致。
