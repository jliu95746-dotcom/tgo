## 实际发现：步骤导航重复保存

企业问题版本改变岗位要求后，启用检查显示版本变化；通过向导内“修改 → 保存岗位与渠道”确认当前要求后，页面正确显示“待评审”，启用按钮不可用。随后“前往独立试聊 → 下一步：核对与启用”重复 POST 原草稿员工保存接口，实际返回 HTTP 409：`员工配置尚未保存，请恢复原草稿后重试`。向导丢失原已确认员工回执并停在保存失败。

原因是每次后续步骤都调用 materialization（将草稿保存成员工），而独立岗位编辑已按原设计改变该岗位的来源归属；继续同一配置的页面导航不应再次写入或覆盖它。当前员工、问题版本和六份模型结果均已真实保存，409 不表示创建失败，不重建同名员工或重发模型请求。
