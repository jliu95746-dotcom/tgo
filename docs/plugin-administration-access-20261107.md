十项管理 API 从仅要求有效员工身份改为现有 `require_admin` 管理员规则；调试令牌本来就要求管理员，未改变其规则。普通员工不能继续通过直接调用接口绕过菜单限制，这是本批明确的权限行为变化。

新增请求授权绑定复用现有 `require_profile_access`、原身份快照、`profile_guard` 和 `CurrentAccessRoute`，不建立另一套身份框架：

- 在调用 Runtime 前核对实际令牌持有人、员工、企业和角色。
- 安装列表及十项管理入口在响应头、响应正文和流式进度发送处复核原授权。等待期间降权、停用、删除、换企业或撤销令牌后，不把旧请求的配置结果继续发给浏览器。
- 已经发起的安装/升级等外部动作不会因浏览器停止接收就自动回滚；本批验证的是发起前授权和后续输出限制，不声称撤权能撤销已经完成的操作，也没有增加自动重放。
- 隐藏来源地址只作用于员工响应模型副本，不改 Runtime 原始响应、数据库或管理员的更新配置，避免把掩码写回并破坏升级。

前端已安装插件类型补为 `source_url?: string | null`，与后端既有可空 Schema 一致。组件采用外层角色检查，管理员原主体的完整初始化函数文本、CSS 类名和文案保持；没有增加提示弹窗或改版。原组件已超过 800 行，本次评估后仅增加外层门禁，未将全组件拆分重构混入授权修复。
