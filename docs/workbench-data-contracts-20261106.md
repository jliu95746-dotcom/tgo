## 实现与保持的行为

已有活动更新接受 `occurred_at: null`，但数据库时间列不允许空值。原实现把空值写入，触发数据库约束错误。现空时间与未提供时间一致：更新保留原活动时间，创建使用当前时间；有效时间仍按客户提交值保存。标题及其他原有更新行为保持。

工作台数据接口同步收敛了以下类型问题：

1. 员工响应按既有 `StaffResponse` 校验原字典，明确可空的工作状态；员工和客户列表使用既有 `PaginationMetadata`，返回字段与筛选规则保持。
2. 标签筛选显式提供 `select`，与原先隐式转换后的 PostgreSQL SQL 和参数一致；正常中英文列表、分页和项目隔离有实际 ASGI/SQLite 证据。
3. 客户昵称列表函数保留同一列表和对象，通过泛型保留调用方具体元素类型；没有改变任何响应模型字段。
4. 会话补全和等待列表分开命名局部变量，保持原渠道内容、状态筛选、项目范围和未读处理；历史清理序号只补充 legacy SQLAlchemy `Column` 在实例上实际为整数的类型说明，未更改计算规则。
5. 原生接待辅助函数准确标明原本已经支持的空模式。空模式仍不发起远程操作，正常自动/辅助模式的原接待释放要求保持。直接接待的等待时长注解与既有可空属性一致。
