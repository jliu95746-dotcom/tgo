# 聊天工具调用批次校验与流完成检查

## 已复现问题与实现

`ChatService` 自动执行模式原先直接读取可空的 `ToolCall.function`、名称和参数，并在流式解析异常时忽略异常继续。模型未正常完成、调用字段缺失或多个候选混用时，可能进入执行或出现 `AttributeError`；整批尚未检查完就已创建执行协程，失败用例还产生未等待协程警告。

新增 `app/services/chat_tool_calls.py`，供流式和非流式共用：

- 执行前检查整个当前批次的工具编号、名称、完整 JSON 对象参数和同批编号唯一性；拒绝重复 JSON 键、非有限数字、空或不完整字段。先完成校验，再创建执行协程和追加助手工具消息。
- 自动执行要求当前主候选明确返回 `finish_reason=tool_calls`；流式还需正常终止标记。中断、供应商错误、非法帧或完成后继续追加调用数据时停止当前批次，不把 EOF 当成功。
- 工具增量按工具 index 组装，重复出现的相同完整编号保留，编号改变拒绝；只从候选 0 组装，保留其他原始候选帧的传输。
- 校验后使用不可变的调用值进入原 `ToolExecutor`；仍由既有执行器校验工具注册和项目范围，没有新调用旁路。
- 非流式使用原 `CHAT_COMPLETION_ERROR`，HTTP 状态保持 500；流式沿用 `error/type=api_error` 结构和单次 `[DONE]`，提示使用固定中文，不输出参数、供应商异常文本或堆栈。取消继续向上传播。

`auto_execute_tools=false` 的原始代理模式继续原样透传模型响应；没有收紧公开的部分增量 schema。已成功执行的前轮结果保留，不因后轮校验失败回滚或重复执行，提示明确限定“本轮工具未执行”。本批没有新增跨请求业务幂等机制。

修改限于 AI 内部工具协议与聊天服务，没有 API 字段、数据库模型或迁移变更。原 `chat_service.py` 仍超过 800 行：把新状态和校验独立到小模块，本批保留原供应商客户端，避免同时重构其他模型与消息转换。
