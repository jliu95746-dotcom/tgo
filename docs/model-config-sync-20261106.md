## 问题与修复

1. 供应商启用接口提交状态后没有返回声明的响应，正常调用会触发 `ResponseValidationError`。现返回既有 `AIProviderResponse`；保持原项目及删除过滤，正常和同步失败都返回实际保存状态，密钥继续掩码。
2. 两个配置同步客户端原来把重定向、空正文、非法 JSON、错误对象或另一批配置的响应当作成功。现只接受 2xx、JSON 对象及 `data` 数组，核对完整数量与供应商 `id`／配置 `project_id`，拒绝遗漏、重复及编号不匹配；顺序不同和额外 JSON 字段保持兼容。
3. 比较编号在请求发送前保存，不从等待期间可能变化的 ORM 对象重新取得。成功后沿用既有数据库状态更新；失败保存静态摘要，原始响应正文、异常详情和凭证不进入这两条同步路径的错误信息。启用接口的同步异常日志也去除原文。
4. 请求格式、服务认证头、HTTP 客户端参数、既有指数退避次数和延时保持。准备载荷异常受控失败；无效非字符串 vendor 不转换为另一个可用供应商；取消仍向上传递。
5. 同步接口使用明确 JSON 类型与结果类型，数据库参数补 `Session` 注解；没有模型、迁移、公开 Schema、依赖、环境配置或权限规则变化。

“已同步”只说明 AI 服务对该批配置返回匹配回执，不等于真实模型测试通过、嵌套模型已完整读取，或后续异步向量库配置完成。未新增跨进程修订版协议，也未完成真实 PostgreSQL 并发修改验收。
