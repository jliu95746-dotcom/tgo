## 实际问题

当前客户回复发布路径发送的是嵌套事件，例如外层 `event_type=agent_content_chunk` 的 `data` 中仍包含 `event_type` 和 `data.content_chunk`。旧 `/chat/completions` 适配只读取第一层 `content_chunk`，会丢失已经核验和发布的正文，却仍发成功结束标记。

旧实现还存在这些可复现问题：单次最终正文未转为输出；异常事件或意外 EOF 没有明确结果；异常原文会进入响应；共用 Schema 的字符串清理会改变分段空格和换行；收到第一个完成事件就停止读取，无法保证后继任务清理已完成。

这些问题在固定起点的适配函数上通过隔离回归及本机 HTTP 重放复现。该证据不表示已在当前云端复现或修复。

## 已完成的实现

1. 保留 `/chat/completions` 入口、当前访客权限、调用身份和服务参数；将格式转换放入独立服务，原鉴权、分配和非流式处理继续使用原路径。
2. 同时读取现行嵌套事件和旧的直接载荷；只接受字符串正文，错误形状不冒充回答，不把结构化数据转换为文字输出。
3. 保留有效分段的空格、换行和 Unicode。正文已做类型核验，再构造现有 Delta 模型以避免共用 Schema 再次裁剪文字，没有修改公开 Schema。
4. 无分段但有有效 `final_content` 时输出一次完整回答；已有正文时不重复发送最终文本。
5. 完整读取上游到结束、执行其清理后，才发送一次成功完成和 `[DONE]`。清理失败、完成后失败、异常或无有效完成的 EOF 返回固定失败信息和一个 `[DONE]`，不会同时宣告成功。
6. 消费者主动关闭或任务取消继续向上传递，并关闭事件来源；不自动重试或重新生成回复。
7. 显式声明兼容接口的响应类型，并以 `response_model=None` 保留原公开响应定义；完整 OpenAPI 对比确认一致。

修改文件为 `app/api/v1/endpoints/chat.py`、`app/services/openai_chat_stream.py`，以及 `tests/test_openai_completion_boundary.py`、`tests/test_openai_stream_lifecycle.py`、`tests/test_openai_stream_http.py`、`tests/test_chat_agent_only_endpoints.py`，均位于 `repos/tgo-api/`。
