## 已实现

1. 历史快照结构异常时，当前记录返回固定中文提示、空正文和空输入；编号、真实状态、作者、审核人、时间和恢复来源照常显示。其他版本继续读取。读取操作不修复或重写数据库，错误响应不包含损坏字段及 Pydantic 输入诊断。
2. 发布、提交审核和恢复共用完整性校验。无正文、无效向量、损坏快照以及不完整的问答返回受控 `409`；恢复在删除旧的“无变化”记录、创建新修订之前校验。跨企业请求仍为 `404`。
3. 历史清理只从对象快照读取非空字符串路径。JSON null、数组、字符串或非字符串路径不再导致整个清理失败；仅按原先预览与确认的版本集合清理。无法证明归属的文件路径不会自动转换或删除。
4. 保留合法资料的提交、发布、恢复与原有普通文件规则；损坏的草稿仍可放弃，原生效文档保留。前端原有 `version.error` 展示入口即可显示提示，未增加第二套界面。
