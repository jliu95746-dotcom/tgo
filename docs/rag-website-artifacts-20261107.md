## 实现

1. 网站抓取、分段、相同内容判断与向量校验先在内存完成；模型失败、取消或任务已过期时，不提前写入网站正文。
2. 最后复核当前版本状态、处理批次和资料归属后，在对应资料的数据库锁内写入专属目录。目录使用来源和随机文件编号；独占创建，不能覆盖已有目录。先写并同步归属收据，再写并同步 UTF-8 正文；收据只含企业、来源、版本、批次及路径，不复制网站正文。
3. 正常返回、失败或取消后，重新用数据库引用确认能否清理。提交实际成功但响应中断时，已保存的版本或文件引用会保留正文。无法确认数据库状态时保留收据，交给后续任务处理，不直接删除。
4. 后台清理跳过正在写入的来源；来源已删除时仍检查文件和版本引用。引用检查包含旧挂载路径后缀及大小写差异，其他来源/企业的已有引用也会保护文件。收据关联的草稿、待审核、已生效或历史版本记录本身也构成引用，快照损坏或丢失路径时仍保留正文，供人工恢复。清理使用当前事务读到的最新引用，不能确认或事务隔离不合适时保留文件。
5. 只清理配置上传目录下的专属目录。拒绝符号链接/路径别名、归属不一致、未知子文件和含正文的损坏收据。没有正文的空目录或残缺收据可以恢复清理；旧上传根目录中无法证明归属的 `version-*.md` 文件不凭名称猜测删除。
6. 清理任务之间通过事务锁避免重叠；使用持久化游标轮转批次，避免已有引用的记录一直挡住后续条目。单文件文件系统错误保留待后续处理；数据库/调度故障使用固定错误摘要和最多三次退避重试，不输出原始异常正文。

收据恢复针对进程异常退出和暂时故障，不代表已经完成断电、磁盘故障或生产备份恢复验收。
