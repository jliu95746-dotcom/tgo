## 问题与修改

| 情况 | 修复前 | 当前候选行为 |
| --- | --- | --- |
| 新项目还没有分配规则，打开接待设置 | 把逗号分隔的日期字符串传给数组字段，响应校验失败 | 读取与首次保存共用经校验的默认配置，返回日期数组；读取不创建记录 |
| 首次只保存接待容量等设置 | 省略智能分配开关时，创建记录会隐式设为开启，与读取默认值不一致 | 默认保持关闭；明确提交 `true` 才开启 |
| 对已有规则只修改其他设置 | 应保留原有开关选择 | 继续保留；明确提交 `false` 可以关闭 |
| 显式提交空的智能分配开关 | 首次保存可能隐式开启；更新已有记录会触及非空数据库约束 | 返回 HTTP 422，在查询供应商和修改规则前拒绝，不保存同请求中的其他字段 |
| 读取或修改规则 | 日志包含员工用户名，可能是邮箱 | 不记录用户名、提示词和请求正文；保存日志只保留事件及项目、规则编号 |

分配业务逻辑移到 `app/services/visitor_assignment_rule_service.py`，原端点保留原来的读取/更新权限，项目范围始终来自已认证员工。供应商仍需属于当前项目且未删除；供应商不可用时不修改其他字段。已有可空的提示词、模型和供应商字段仍可清除。

默认日期去重并排序；默认环境配置也经过已有创建 schema 的校验，不再静默丢弃非法日期后继续保存。数据库结构保持原样，没有为类型或格式修改添加空迁移。
