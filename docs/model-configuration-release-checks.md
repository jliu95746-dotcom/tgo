# 模型配置发布检查与试聊失败分类

## 要解决的问题

云端曾出现 API 开启 SaaS 计费、AI 关闭计费的错配。两端采用了不同的模型执行上下文，模型配置核验拒绝执行，试聊只留下 `execution_failed`。本批为该实际故障补发布前检查和明确失败分类，不改变模型签名核验或额度授权要求。

## 发布前检查

在能访问目标 Docker 的主机上，从项目根目录执行：

```bash
python3 scripts/release/preflight_model_configuration.py \
  --api-container yujian-api \
  --ai-container yujian-ai \
  --require-billing
```

容器名由参数指定。工具只读检查两个容器，单次 Docker 检查最长 10 秒。输出仅包含检查项状态和固定原因：

| 检查项 | 要求 |
|---|---|
| `service_identity` | 两个不同容器，Compose 服务分别为 `tgo-api` 和 `tgo-ai` |
| `container_health` | 两个服务均处于 running、healthy |
| `saas_mode` | 两端 `SAAS_ENABLED` 的有效布尔值一致 |
| `billing_mode` | 两端 `SAAS_BILLING_ENABLED` 的有效布尔值一致 |
| `billing_requires_saas` | 计费开启时，SaaS 同时开启 |
| `required_billing` | 指定 `--require-billing` 时，两端均开启上述两项 |
| `model_proof_key` | 两端用于模型证明的 `SECRET_KEY` 已配置且相同 |
| `quota_authorization_key` | 计费模式下，两端 `SAAS_INTERNAL_TOKEN` 已配置且相同 |

两个开关需显式配置为可核验的布尔值；缺失时不猜测镜像内配置文件的默认值。相同空密钥、非法布尔值、大小写重复却冲突的环境项、不可核验的角色或健康状态均不能通过。环境配置只在检查进程内比较，结果中不包含凭证原文或其摘要。未使用计费的合法安装可省略 `--require-billing` 并显式设置关闭状态，但模型证明密钥仍需一致。

退出码 `0` 为本检查通过，`1` 为配置不一致或无法核验，`2` 为 Docker 检查不可用。升级流程应在非零结果时停止切换，保留原服务并修正配置后重验。本工具的范围是配置一致性，后续还需 API 运行、页面和业务验收。

镜像发布工作流的服务发现步骤前已加入工具单元测试，测试失败会阻止后续服务发现和构建；目标主机的真实配置检查仍由上述命令执行，CI 不读取生产凭证。

## 试聊报告与日志

模型证明校验增加 `ModelConfigurationVerificationError`，保持 `ConflictError` 的现有继承和对外冲突处理。只有模型核验产生该专用类型，普通业务冲突不会被误报为模型配置错误。

| `error_code` | 报告状态 | 含义 |
|---|---|---|
| `model_configuration_unavailable` | blocked | 当前模型与所有者证明不一致或配置不可用，请核对模型与服务同步 |
| `authorization_denied` | blocked | 账号、模型或额度授权未通过 |
| `dependency_unavailable` | failed | 依赖服务调用未完成 |
| `timeout` | failed | 试聊超时 |
| `execution_failed` | failed | 其他未分类执行异常 |

原有知识检索不可用、超预算、没有匹配资料及生成失败分类保留。模型核验和授权在生成前停止；无回答报告沿用 API 现有额度释放逻辑，不会因新错误分类自动获得能力通过。历史报告保持原记录，不用猜测的新原因覆盖旧 `execution_failed`。

新增事件名为 `agent_trial_execution_issue`，字段为 `report_id` 和固定的 `failure_code`。日志关联原持久报告，不记录异常消息、堆栈、问题正文、模型密钥或服务响应。试聊重试仍查询原回执；取消、超时及正式员工启用状态遵守原规则。
